# Windows portable bundle (no installation required)

This guide explains how to build a Windows portable bundle, what it includes, what it leaves out, and what to check before sharing it.
Related code: `scripts/make-windows-bundle.mjs` (builds the bundle) and `scripts/launch.mjs` (prepares the app, starts the server, and opens a browser).

## 1. What this bundle is for

The bundle has one purpose: **turn this Windows PC into the game server**. It includes Node.js, game assets, and production dependencies.
The target PC does not need anything installed: double-click `Start-Game.bat` to start a local server and open the game in a browser.
The console prints a LAN address that you can share with friends (for solo play or to play with friends on the same home, school, or office network).

**You do not need this bundle to join someone else's server.** Just open their URL in a browser. Your PC does not need to run a server or download game assets. The bundle therefore has no “join server” launcher.

## 2. Build a portable bundle

First prepare the assets. These directories are not tracked by Git:

```sh
node tools/setup.mjs
```

Then run one of these commands from the repository (**on any platform**, with Node 22+ and internet access to download the official Node.js archive):

```sh
node scripts/make-windows-bundle.mjs                                      # Defaults to <parent of repository>/Stronghold-Protocol-Windows
node scripts/make-windows-bundle.mjs --out D:\Game\Stronghold-Protocol-Windows --force
node scripts/make-windows-bundle.mjs --no-node                            # Omit portable Node if the target PC already has Node 22+
node scripts/make-windows-bundle.mjs --node-version v22.23.3 --sha256 <64-hex-digits>  # Select another Node version
```

Give `--out` a **dedicated directory**, such as a new subdirectory under a parent folder. With `--force`, the script only removes an empty directory or a previous bundle (identified by `README-Quickstart.md` and `app\` at its root). It refuses all other existing directories to avoid deleting a repository, Desktop, or other files by mistake. An output path pointing to the repository itself or one of its parent directories is rejected immediately.

The result is always a **Windows** bundle containing `win-x64` `node.exe`, but it can be built on macOS or Linux too: the official archive has the same `<zip name>/node.exe` layout on every build host.

Bundle contents:

```
node\node.exe                   Official Windows x64 portable Node.js (version and SHA-256 are pinned in the repository)
node\LICENSE-node.txt           Node.js license (MIT, from the same official archive)
app\                             Game files, production dependencies, public assets, and data; works offline
Start-Game.bat                   Runs app\scripts\launch.mjs --no-setup
README-Quickstart.md             Player instructions and project, asset, and copyright notices
LICENSE / NOTICE.md / THIRD-PARTY-NOTICES.md
```

Copy the whole folder to the target PC. **Nothing needs to be installed**; double-click `Start-Game.bat`. It runs
`app\scripts\launch.mjs --no-setup`: assets are already included, so setup is skipped and the server starts directly.
To uninstall, delete the folder; the bundle does not write to the registry or install files in system directories.
Assets account for about 330 MB, so the bundle is fairly large.

## 3. What the bundle includes and excludes

The `app\` file list comes from **`git ls-files`**, not from a manually maintained exclusion list. Local files ignored by Git
(`.env`, `.venv*`, `.claude/`, `scripts/service.env.cmd`, and similar files) cannot accidentally end up in the bundle.
They may contain credentials or machine-specific paths; the previous approach copied the whole tree and relied on a short exclusion list.

The builder also adds three required directories that are not tracked by Git, and freshly installed production dependencies:

* `public/assets`, `public/fonts`, and `public/vendor` (downloaded or generated by `tools/setup.mjs`);
* `node_modules`, installed with `npm ci --omit=dev`. Development dependencies such as `puppeteer-core` are used for tests and are not included in the bundle;
* `data/local-assets.json`, if present (created when local 3D board textures have been extracted). The textures themselves live in `public/assets/local` (about 68 MB) and are included with `public/assets`. The game needs the JSON manifest to discover them. Without it, the textures take up space but are unused. If the manifest is missing, run `node tools/setup.mjs --local`.
* `test/` is excluded to reduce bundle size.

During directory copies, symbolic links and dot-prefixed entries are skipped. For example, the build machine's `.DS_Store` file is not part of the project and should not be shipped.

The Node.js version and SHA-256 are pinned in `NODE_PIN` in `scripts/make-windows-bundle.mjs`; the builder does not use a moving `latest-v22.x` version. Pinning makes builds reproducible. To select another version, provide a specific `vX.Y.Z` version with `--node-version` and its `--sha256`.

The official ZIP download is cached under the repository's `.cache/` directory (which is not tracked). The builder **extracts `node.exe` from the verified ZIP every time** into a new temporary directory and deletes that directory afterward. It caches the ZIP, not the extracted executable: a partial `node.exe` left by an interrupted extraction is not guaranteed to match the verified archive. The extractor tries `tar`, then `unzip`, then Windows' built-in `Expand-Archive`.

The `--out` and `--force` safeguards work together: output paths at or above the repository are rejected. Elsewhere, `--force` can remove only an empty directory or a directory that matches the previous bundle markers (`README-Quickstart.md` and `app\`). All other directories are left untouched. Path checks alone cannot account for every case involving letter casing, symbolic links, or Windows 8.3 short names, so the builder only deletes output it can identify as its own.

## 5. Troubleshooting

| Symptom | What to do |
|---|---|
| The `.bat` window closes immediately | Run `Start-Game.bat` from a terminal to see the error, or run `node\node.exe app\scripts\launch.mjs --no-setup` manually (`.bat` pauses after a non-zero exit). Keep `--no-setup`: without it, the launcher tries to download assets and may not find `node` on PATH. |
| “Node not found” | A portable bundle should contain `node\node.exe`. If you used `--no-node`, install Node.js 22 or 24 LTS yourself. |
| The port is already in use | Close the program using port 3000 (`node tools/doctor.mjs` can identify it), or add `--port 3001` to the launch command. |
| The browser did not open automatically | Visit `http://127.0.0.1:<port>` manually. `--no-open` or `SP_NO_BROWSER=1` disables automatic browser opening. |
| Friends cannot connect | Check that Windows Firewall allows the app on private networks and that everyone is on the same network. Run `node tools/doctor.mjs` to diagnose; see the firewall section in [DEPLOY.md](DEPLOY.md) in the source repository. |
| A download prompt appears when entering the game | Download managers such as IDM or Xunlei may mistake audio URLs for downloads. A recent version serves media through extensionless `/media/…` routes (see [PR #28](https://github.com/sganggs/Stronghold-Protocol/pull/28)), which should prevent the prompt. If it still appears, attach the URL to an Issue, add an exception such as `http://127.0.0.1:3000/*` in the download manager, or close it while playing. |
| The first game load is slow | Each player downloads tens of megabytes of assets once (served from the host PC's disk); later visits use the browser cache. |
| Extraction fails while building on Linux | GNU `tar` cannot extract ZIP files. Install `unzip`, or build on macOS or Windows. |

## 6. Security and size

* `node.exe` comes from the official nodejs.org release and is copied only after its SHA-256 matches the value pinned in the repository. It is not modified. The matching `LICENSE` is included as `node\LICENSE-node.txt`.
* `app\` contains only tracked project files, production dependencies, assets, and the optional 3D board manifest. Locally ignored files such as `.env`, `.claude/`, and `scripts/service.env.cmd` are excluded.
* The game does not write to the registry or install a service. `Start-Game.bat` only switches the console to UTF-8, locates `node\node.exe`, and runs `app\scripts\launch.mjs --no-setup`.
* To run the game as a Windows service on startup, use the repository's `scripts/install-service-windows.ps1` (for packaged or source deployments; see [DEPLOY.md](DEPLOY.md)).
